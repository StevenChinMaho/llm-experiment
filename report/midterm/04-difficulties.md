## 2. 預計可能遭遇之困難及解決途徑

| 困難 | 解決途徑 |
|---|---|
| **VRAM 不足**：27B 模型以 16 位元儲存需 51 GiB | 權重量化；KV cache 以 q8_0 儲存；不載入視覺模組；關閉獨顯的螢幕輸出；以 2.1.5 的記憶體模型事先估算 |
| **作業系統默默超用記憶體**：Windows 把超出 VRAM 的部分放到系統記憶體，讀取 prompt 的速度只剩 10～39%，生成速度卻不變 | 正式實驗只在 Linux 上進行，放不下時直接配置失敗；在 Windows 上以「共享 GPU 記憶體」計數器監看 |
| **兩台機器的軟體版本不同**：初期分別為 build 10751（conda）與 11347（Docker） | 兩台都改用 Docker，以映像 digest 固定同一個 build，驅動也統一版本 |
| **思考無上限而耗盡 context**：曾有一題思考約 8.2 萬 token 仍未作答 | 以 `--reasoning-budget` 限制思考長度，並保留作答空間 |
| **模型與資料都可能出錯**：模型會算錯長數字；公開資料集有 2 題抄寫錯誤 | 一律以程式批改；標準答案以獨立程式或第二份資料來源交叉驗證 |
| **推測解碼中途記憶體不足、題目太簡單**：n_max 過大時首次推論才中止；校準答對率達 90～100% | 以 2.1.8 的遞迴狀態公式限制 n_max；以思考預算與量化等級拉開比較條件，避開天花板 |
