# 一、研究計畫之背景及目的

## 1. 背景、目的與重要性

### 背景

大型語言模型（Large Language Model, LLM）已成為程式撰寫、資料整理與知識問答的日常工具，但多數使用者是透過雲端服務取得這項能力。雲端服務有三個限制：一是資料必須上傳到第三方，不適合處理個人資料、未公開的研究資料或企業機密；二是依使用量計費，長時間、大量的使用成本可觀；三是必須連網，服務中斷或政策變動時無法自主控制。隨著開源權重模型快速進步，在個人電腦上部署本地 LLM 已成為可行的替代方案。

然而，消費級顯示卡的顯示記憶體（VRAM）有限，常見的是 8GB 到 16GB。以本研究使用的 Qwen3.8-27B 為例，約 273 億個參數的模型以 16 位元浮點數（BF16）儲存需約 51 GiB，遠超過一般顯示卡的容量。因此本地部署幾乎必須依賴**量化**（quantization），將權重壓縮到每個參數 2 到 5 位元。量化降低了記憶體需求，卻也可能降低回答品質；而剩下的 VRAM 又要分給 context（對話與文件的長度）所需的快取，以及加速生成的輔助模組。使用者面對的不是「能不能跑」，而是「有限的 VRAM 要怎麼分配」。

近來的模型還有兩個新特性，使這個問題更值得重新檢視。第一，**混合架構**：Qwen3.8-27B 的 64 層中只有 16 層是需要 KV cache 的全注意力層，其餘 48 層是記憶體大小固定的遞迴層。本研究的初步量測顯示，每個 token 的 KV cache 只需 34 KiB，約為以傳統架構估算（256 KiB）的 13%；連同運算暫存，每增加一個 token 的 context 也只多用 39 KiB 的 VRAM（由實測歸納，見 2.1.5）。context 變得很便宜，真正佔用 VRAM 的是權重。第二，**思考模式**：模型在回答前會先產生數千到上萬個思考 token，答對率與「想多久」有關，而生成速度決定了相同時間內能想多久。

### 目的

本研究以兩張消費級顯示卡（RTX 3060 12GB 與 RTX 5060 Ti 16GB）部署 Qwen3.8-27B，透過系統化的量測，回答一個核心問題：

> **VRAM 固定時，資源應該花在權重精度、context 長度，還是讓模型多想幾個 token？**

並拆成四個研究問題：

- **RQ1**：量化等級如何影響模型品質（KL 散度、困惑度）與推論速度？
- **RQ2**：在 12GB 與 16GB VRAM 下，最佳的設定為何？包括權重精度、可用的最大 context，以及推測解碼（MTP）的速度提升與 VRAM 代價。
- **RQ3**：在相同的等待時間下，「低精度、多思考」能否補回「高精度、少思考」的答對率？
- **RQ4**：讓模型呼叫計算工具，能否修正本地模型常見的算術錯誤？

### 重要性

本研究的重要性有三點。其一，提供**可重現的實測數據**：兩台機器使用相同的驅動版本與相同映像 digest 的推論引擎，每筆數據都附完整環境紀錄，讓結論只反映硬體與設定的差異。其二，提供**可預測的記憶體模型**：初步結果顯示，由啟動紀錄歸納出的公式能在實驗前預測最大 context，誤差約 2%（見 2.1.5），使用者不必反覆試錯。其三，提供**依任務而定的部署建議**：學生、研究室與小型組織可以依自己的顯示卡與用途，選出合適的量化等級與參數，以平價硬體建立兼顧隱私與成本的私有 AI 服務。
